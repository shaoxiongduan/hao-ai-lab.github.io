Thinking while the arms move

An LLM agent writes Python against the robot API to find a pear under one of three cups and hide it under the empty one. Every model call costs seconds. The harness lets those seconds pass while the arms are already moving. Step through what each piece of the harness takes off the clock.

3.2x faster than a vanilla agent loop; 1.8x from the queue alone. Same work in every row: 14 actions, 153 s of arm motion, about 60 model responses. The measured run finished in 211 s, against 674 s for the modelled vanilla loop and 374 s for the same harness without the queue. The robot was moving 84% of the time from its first motion to the finish, and 137 of the 186 s of model time ran while the arms moved. Fast IK would take about 0.9 s more off this run (projected ~3.2x).

How the earlier stages are estimated

Stage 5 is the real run, drawn from its event log. Stages 0 to 4 are modelled: the same measured events, replayed without each harness piece by these rules. Stage 6 is projected from IK benchmarks taken after the run.

  1. Same work in every stage: the 60 measured model responses, 57 tool calls and 14 actions (153 s of motion) of cups-02, in the same order.
  2. Stages 0-4 have no queue: each action is a blocking call, so the model waits through the motion and the robot waits through the model.
  3. An extra turn costs the measured median model response (2.58 s, 74% of it waiting for the first token) plus a measured tool time.
  4. No pushed reports (stages 0-3): one polling turn after each action to read its result, state and a camera capture (0.66 s, the median camera cell).
  5. No same-step images (stages 0-2): each image read is its own view_image turn (0.05 s tool time assumed); 23 images the programs showed, plus the 14 after-action captures (2 of the 23 are camera grids).
  6. No camera grid (stages 0-1): each camera capture is 4 full-size 640x480 images, read in 4 turns. Images kept in context slow the first token: +0.54 s per 100 images and +0.21 s per 10k image tokens (bench_grid fit, speed-measurements.md), here +0.14 s per response.
  7. No batched checks (stage 0): the 12-pose placement sweep is checked one pose per turn until the first reachable one (pose 10): 9 extra turns. The 2- and 3-pose checks stay in one program.
  8. Pushed reports (stage 4) add the measured median delay from action end to report (1.04 s).
  9. Fast IK (stage 6) scales the run's reachable-check times by 0.34/1.4 and failed IK by 40/141, then replays the queue; the actions keep their measured durations.
  10. Robot idle = wall time minus motion. Model time hidden = model time that overlaps robot motion.
